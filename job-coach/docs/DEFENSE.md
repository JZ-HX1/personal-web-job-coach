## 四分钟演示

1. 双击 `start.bat`，打开 `http://127.0.0.1:8501`，点“体验示例”。说明虚构档案不是真实简历。
2. 查看目标和材料类别，进入“公司/岗位推荐”，展示虚构岗位库、推荐排序、原文证据与补齐建议。
3. 输入：“根据我的材料推荐适合的岗位，说明差距，并导出推荐清单。”展开执行记录，指认真实工具和结果。
4. 下载 CSV / Excel 清单；再展示简历与一个【需确认】项，说明分数不预测录用、没有编造成果。
5. 练习一道面试题，查看评分口径。记录虚构岗位，展示人工确认前后台账的差异。

模型连接失败时说明原因。普通按钮可以展示业务后端，但必须明确不是实时 Tool Calling，不能拿普通业务结果冒充模型调用。

## 常见问答

**为什么是路径 B？** 求职档案、匹配、面试和台账有独立业务接口，Agent 使用这些接口完成自然语言任务。

**模型与程序如何分工？** 模型选工具并生成参数。服务端校验输入、限制档案范围、执行规则并保存真实结果。模型不能直接写 SQL 或任意文件。

**一句话多步骤必须产生多次模型调用吗？** 不必须。模型可以调用 `analyze_fit` 并传入 `export_kind="bundle"`，由适配层依次分析匹配与生成材料包。执行记录只有一次模型调用，内部包含多个实际业务操作。独立简历与导出工具仍可分别调用。不能把服务内部操作伪称为多次 Tool Calling。

**是不是关键词路由？** 对话意图到工具选择来自模型 `tool_calls`。技能词表用于业务层的可解释匹配计算，两者不同。

**不是仅换提示词的证据？** 新增目标档案、材料来源边界、文件解析、匹配与能力映射、STAR、逐题练习、台账确认和多格式导出，均有后端与界面实现。

**匹配率能预测录用吗？** 不能。它只反映 JD 中可识别技能与当前个人材料的覆盖，不能测量实际能力、竞争情况和招聘偏好。

**如何减少简历编造？** 个人事实仅来自简历、项目、成绩单、技能清单、证书和作品集等个人材料。JD 和范例不充当经历。保守整理、原文引用与【需确认】提示降低风险。没有工具调用时只展示流程引导，个人履历文本统一由有来源的业务工具生成，使用前仍需本人核对。

**使用 AI 工具就等于模型训练能力吗？** 不能。只能映射材料实际支持的能力。

**推荐引擎如何超出简单关键词比对？** 使用可解释的同义词归一化和明确的相关技术关系。真正同义的写法可以合并，Spring 与 Spring Boot 等相关技术只给部分适配，原文证据和缺口仍保留。这是规则关系匹配，没有使用通用向量语义模型。

**推荐公司是不是实时招聘名单？** 不是。它比较用户手动录入的 JD 和公司资料。公司技术栈、业务方向和文化只引用现有资料，没有资料就标记需确认。虚构示例不表示真实公司正在招聘。

**技能雷达图能证明能力强弱吗？** 不能。它汇总材料中的证据覆盖，材料写得少或未被词表识别都可能导致低值。它不能替代技术测评、项目审查或真实面试。

**补齐后如何重新推荐？** 实际完成学习或项目后，加入新的个人材料，再点击重新匹配。更新证据与岗位内容会使旧结果失效。单纯声称“已经会了”不能补造项目或证书。

**面试评分意义？** 检查背景、个人行动、结果和反思是否清楚。评分绑定本轮用户实际输入，准备好题目后先等待作答，不让模型代答后自行评分。不判所有技术答案正确，也不等同企业分数。

**为什么台账修改要确认？** 避免小模型误记公司、状态和日期。模型只准备变更，本人通过独立接口确认。没有对外投递或发邮件。

**知识库是不是向量 RAG？** 当前是本地文本检索与来源引用，没有嵌入模型或向量数据库，应说明实际方式和限制。

**用了框架、MCP、Skill 吗？** 自建轻量循环，没有 LangGraph、MCP 或规范化 Skill。路径 B 不强制要求这些组件。

**数据在哪里？** `runtime/career/`。默认模型服务在本机。仓库忽略真实材料和运行数据。会话编号不是正式登录认证，只适合本机教学原型。

**AI 辅助范围？** Codex 协助分析、实现、测试与汇报。本人应能解释关键函数，并如实说明自己的运行、学习和修改。
